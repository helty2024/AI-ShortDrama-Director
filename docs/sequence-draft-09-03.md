# 09-03 项目时间线草稿持久化

验收日期：2026-10-27。分支：`codex/09-01-test-ready-alpha`。

## 保存范围

- 正式镜头的批准、采用绑定继续由既有 SQLite 逻辑保存，不会自动采用候选。
- 每个项目保存一份 `sequenceDraft`，附在现有 `projects.data` JSON 中：格式版本、草稿修订号、保存时间，以及有序的镜头 ID、视频版本 ID、入点和出点。旧项目无此字段时正常打开，无新增表、迁移、依赖或 preload 权限。
- 建线、修改区间、载入历史成片都会自动保存；显示“时间线草稿已自动保存到本地”后可关闭应用。离开页面返回或冷启动进入分镜视频，自动恢复草稿，无需先导出或从历史载入。
- 保存按编辑顺序执行；页面切换后的读取等待上一页面的保存队列。草稿修订号阻止另一窗口静默覆盖。失败显示原因和重试按钮。
- 暂时无效的入点/出点也保存，恢复后继续提示并禁用导出。保存只允许项目内镜头和视频版本，拒绝重复镜头、跨项目引用和额外路径参数。导出继续严格检查当前采用绑定、批准状态、正式顺序、源视频时长及素材完整性。
- 常规项目资料修改保留草稿；删除项目同时删除草稿。重新建立或载入历史时间线会替换现有草稿，不保留多份草稿历史。

## 仍不保存／未扩展

- 播放位置、连续播放状态、候选预览和面板展开状态不属于时间线草稿；已有批次时间线仍沿用显式保存流程。
- 保存成功之前强制终止进程或断电，不承诺最后一次编辑已经落盘；未增加云同步。
- 改变采用版本、删除镜头或改变正式顺序后，保留旧草稿供查看，阻止过期序列导出，需重新建立。
- 当前入口仍使用全部有效确认镜头，不新增任意重排、部分选片、字幕、转场或多音轨。
- 导出仍为最多 100 镜头、600 秒，首镜分辨率、24 fps、无声 MP4，依赖本地 FFmpeg / FFprobe。

## 离线证据

`npm run test:smoke -- --grep "formal project offline"` 在隔离用户目录执行本地红/蓝 MP4 导入、批准、采用，建立跨场次的两镜时间线。先验证无效区间离开页面仍保留并阻止导出，再设置 `0.25–0.75s`、`0–0.5s`，立即导航离开并返回，随后在从未导出的情况下关闭 Electron、重新启动，自动恢复镜头、版本和区间。恢复后连续预览并导出，FFprobe 验证成片约 1 秒；再次重启可载入历史，取消保存提示仍有效。最后核对生成记录、AI 任务和生成批次均为零。

`tests/unit/sequence-export.test.ts` 覆盖旧项目、草稿数据库重开、项目隔离、跨项目版本拒绝、重复镜头拒绝、修订冲突、无效区间保留、项目资料更新不丢草稿、从恢复草稿导出，以及正式顺序改变后阻断。既有用例解码导出画面确认先红后蓝，并阻断过期采用绑定。
